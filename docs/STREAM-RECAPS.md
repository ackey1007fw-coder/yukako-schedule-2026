# 配信コーナー

ホームの `#stream-recaps` に、配信ごとの記録を新しい順で表示します。個別の回は `#stream-YYYY-MM-DD-slug` で開けます。

## 更新する場所

- データと型: `src/data/streamRecaps.ts`
- 共通表示: `src/components/StreamRecapsSection.tsx`
- 並び・日本時間での日付表示: `src/lib/streamRecaps.ts`
- 検査: `pnpm test:stream-recaps`

## 確認段階を分ける

`preparing` は配信日の記録だけです。本文・歌唱曲・スクショを確認した配信メモの件数には含めません。型と表示の両方で、未確認の詳細を出さない設計です。9月16日夜も初期登録はこの状態でした。9月17日に全音声の自動文字起こしを読み、実フレーム10枚とともに配信メモへ更新しました。自動文字起こしの確認と、全編の手動聴取は区別します。

`published` に変える前に、元の配信で本文・固有名詞・曲・時刻を照合します。録画の開始時刻や長さを、実際の配信全体の開始・終了と混同しません。日付・確認日は ISO 形式、時刻は日本時間です。各回のタイムスタンプは録画内の位置を使います。

## 表示の順序

日付・タイトル・一言 → 歌った曲 → 見どころ → スクショ → タイムスタンプ → 配信時点の次回案内 → 出典。項目がない場合は見出しごと省略します。件数を揃えるために内容を増やしません。

- 本文・画像は優花子さんの当該回だけ。参考サイトから引き継ぐのは構造のみです。
- 新しいスクショは実フレームを選び、掲載確認後に追加します。顔の生成・加工はせず、第三者情報が残る画像は使いません。原本や全文文字起こしは公開しません。
- 写真は `public/images/`、承認済みZIPは `public/downloads/`。寸法・alt・キャプション・保存名を記載し、画像追加時は既存の画像生成手順を使います。元画像・既存公開ファイルは上書きしません。
- 曲の `originalUrl` は確認した原曲の公開動画に限り、優花子さんの歌唱動画と区別します。曲名だけの言及を歌唱記録にはしません。
- 次回案内は当時の記録です。現在の `streamSchedule.ts` には自動転記しません。
- 私的情報、視聴者の名前、録画原本のパス・URLはコード・PR・公開データへ入れません。

公開・マージ・画像・検証の条件はルートの `AGENTS.md` に従います。

## ラジオ配信・分割された録画

- 当該配信で表示された画像が1枚だけの場合は `image` を使います。カードの代表画像として1回だけ表示し、本文側には説明と個別保存リンクを出します。`gallery` やZIPで同じ画像を水増ししません。
- `mode: "radio"` はラジオ配信の表示ラベルです。`preparing` の回では画像・ラベル・未確認の本文を表示しません。
- `recording.segmentCount` が2以上なら、長さを「区間の保存分計」と表示します。`durationSeconds` は実ファイルの尺の合計で、開始・終了の壁時計差ではありません。
- 複数の録画を順に並べてタイムスタンプを付ける場合は、`timestampNote` に基準と欠落区間の扱いを明記します。配信中の実際の経過時間や全編の記録とは区別します。
- 9月18日夕方は2本の保存音声を対象とし、1本目の実尺を足した位置から2本目を記載。公開記事には視聴者名・原本パス・全文文字起こしを含めません。
